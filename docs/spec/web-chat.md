# Web 金融问答与开发者追踪规格

状态：已实现并完成本机验收。来源：本聊天中已确认的需求及技术设计。用户于 2026-11-07 明确本轮仅需本机连接，保留内网部署配置，无需内网或外网开放。详细技术解释参见 [设计方案](web-chat-observability-design.md)，完成证据见 [验收报告](../WEB_ACCEPTANCE.md)。本文为产品验收依据，设计文档为实现参考。

## Problem Statement

少量用户需要通过内网浏览器提问并持续查看金融分析回答，而现有产品主要通过 CLI 操作。关闭页面不应丢失任务。开发者需要从用户的一次输入定位模型和工具调用、失败以及延迟来源，同时防止多用户共享聊天或原有本地私有资料。

## Solution

提供登录、隔离的聊天会话、逐字回答和工具状态；后台独立执行已接受的查询任务，浏览器重新连接时恢复消息。管理员通过运行列表和时间线查看脱敏诊断。模型由现有 LangGraph 执行，首版仅使用经审计的只读金融工具。

## User Stories

1. 作为管理员，我希望预建账号，以控制内网用户访问。
2. 作为用户，我希望登录和注销，以保护自己的会话。
3. 作为用户，我希望新建、查看、重命名和删除自己的会话，以管理分析主题。
4. 作为用户，我希望他人不能读取我的会话、结果或推送流，以保证数据隔离。
5. 作为用户，我希望用自然语言查询行情、新闻、指标、选股和回测，以完成金融分析。
6. 作为用户，我希望回答逐字显示，以及时看到进展。
7. 作为用户，我希望看到实际工具的执行状态，以了解等待原因。
8. 作为用户，我希望看到 Markdown 和表格，以阅读结构化结果。
9. 作为用户，我希望看到排队、失败和中断状态，以决定是否重试。
10. 作为用户，我希望刷新、断网或关闭页面后任务继续，以免重新提交。
11. 作为用户，我希望返回页面后看到完整答案，以继续对话。
12. 作为用户，我希望双击提交或自动重连不会重复调用模型，以避免重复结果及费用。
13. 作为用户，我希望同一会话按顺序执行，以保持上下文一致。
14. 作为用户，我希望不同会话可以限量并行，以减少相互等待。
15. 作为用户，我希望服务故障后未完成任务明确标记中断，以免误以为成功。
16. 作为用户，我希望主动重试失败或中断任务，以重新获取答案。
17. 作为用户，我希望分析不会修改持仓、偏好、配置或订阅，以符合只读用途。
18. 作为用户，我希望不会自动读取旧 CLI 用户资料，以免混用个人信息。
19. 作为管理员，我希望按用户、时间、状态及工具筛选运行，以找到问题。
20. 作为管理员，我希望一次输入对应唯一运行编号，以关联诊断信息。
21. 作为管理员，我希望分别查看模型和工具调用，以找到慢环节。
22. 作为管理员，我希望区分排队、首片段、首段正文及执行耗时，以理解延迟。
23. 作为管理员，我希望识别未抛异常的工具业务失败，以准确排障。
24. 作为管理员，我希望同名工具多次调用独立呈现，以避免错误归并。
25. 作为管理员，我希望诊断信息脱敏且不保存内部推理，以控制数据暴露。
26. 作为管理员，我希望模型未返回 token 用量时显示未知，以避免错误统计。
27. 作为管理员，我希望详细追踪到期清理而聊天继续可用，以控制磁盘容量。
28. 作为用户，我希望删除会话同时删除关联诊断，以落实数据删除。
29. 作为运维者，我希望备份、恢复和部署保留旧业务数据，以降低升级风险。
30. 作为现有 CLI 用户，我希望新增 Web 不破坏原 CLI 和 Harness 行为，以继续使用已有工作流。

## Implementation Decisions

- React、TypeScript、Vite 和 Ant Design 实现四类页面；同源 FastAPI API，HTTPS、HttpOnly Cookie、服务端会话和 CSRF 防护。账号首版通过管理命令创建。
- SQLite WAL、SQLAlchemy 和版本化迁移管理用户、认证会话、聊天、已提交模型上下文、运行、事件、调用 span、幂等请求及执行归属。
- 独立 Worker 调度隔离子进程；请求结束不影响执行。默认两路并行、有限队列，均可配置；一个会话最多一个非终态运行，由事务约束保障。
- HTTP 创建运行、SSE 订阅已持久化事件。事件有版本、运行编号和递增序号；快照与游标一致读取，补发和前端去重共同保证恢复。重连不执行任务。
- 回答完成、上下文提交和终态事件原子保存；未提交成功不显示完成。失败/中断草稿不作为成功上下文。
- 模型调用与工具执行边界注入观测；每次执行独立 span，单调时钟计算耗时，UTC 记录时间，页面按北京时间展示。
- 只读工具目录和执行入口双重校验；Web 提示词独立，不读取全局画像，不使用旧用户持仓和订阅。
- 过滤内部推理、原始工具参数片段和凭据。跨片段敏感内容必须覆盖，最终答案走同等过滤。
- Worker 归属代次和进程退出协调阻止迟到写入；Worker 重启后旧未终态任务中断，不自动重试；API 单独重启不停止执行任务。
- 详细追踪默认终态后保留 30 天；恢复事件终态后保留 24 小时，到期通过快照恢复；聊天及必要上下文保留至删除。活动会话删除返回冲突。
- 当前 Harness 不是旁路观测器，首版不要求其原生执行；脱敏及查询能力经验证后复用。原生 Harness 日志事实与 Web 事件严格保留各自来源。
- 应用 API 是主要行为测试边界；真实金融与模型调用通过受控适配器替换，以验证授权、执行、存储和恢复的完整路径。另保留一次真实供应商的受控验收。

## Testing Decisions

- 测试用户可观察行为和持久化事实，不测试函数拆分或重复实现算法。沿用现有 unittest、临时目录和模拟依赖方式。
- 验证账号隔离、撤销登录、CSRF、幂等、同会话并发、队列上限、只读工具越权、重连去重、快照回退和终态原子性。
- 使用可控慢工具、同名多调用、业务错误和模型失败检查时间线，禁止根据批量结果到达时间推断耗时。
- 以实际子进程退出、Worker/API 重启和持久化失败验证恢复；普通浏览器断开不能被误当取消。
- 覆盖跨片段 think 标签和密钥、最终答案过滤、Markdown 注入、详细追踪过期、会话删除和备份恢复。
- 前端完成类型检查、构建、流式 reducer 行为测试及浏览器交互；真实反向代理验证无缓冲 SSE。
- 完成证据必须记录命令、结果及尚未验证项；不能以模拟模型测试替代真实供应商验收或实际部署验证。

## Out of Scope

公开注册、公网开放、用户自带密钥、写入金融业务状态、实时语音、网页关闭后的系统通知、多机高可用、崩溃后自动续跑、用户强制取消、复杂行情看板、旧 CLI 数据自动导入以及强制使用 Harness 引擎。
